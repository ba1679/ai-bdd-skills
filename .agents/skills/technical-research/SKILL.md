# 技術研究

把需求與技術疑問整理成可供後續規劃使用的研究文件，再依研究彙整本次計畫採用的完整技術棧。模板負責產物格式，範例展示完整度；研究決策依本次輸入與查核證據形成，總覽由研究導出。此流程交付文件，不執行套件安裝、產品實作或部署。

# SOP

## Phase 1 -- 收斂研究問題

1. READ 讀取使用者輸入、適用的功能規格、專案規範、既有研究與技術棧總覽；針對既有專案，查閱本次計畫使用的依賴、設定及執行環境，辨識已確認決策、沿用／新增／替換後的採用組合與輸出位置。
2. THINK 收斂研究問題時，先讀取 `rules/research-evidence-and-decisions.md`，再從需求、相依關係及未解限制推導本輪問題，確定各項要支持的規劃決策與研究邊界。
3. WRITE 若缺少會改變研究範圍或結論的使用者決策，提出最小必要問題並記錄待確認事項；繼續處理不依賴該答案的研究。

## Phase 2 -- 查核來源並收斂決策

1. READ 使用可用的查詢或瀏覽工具，依已載入規則查核各問題的官方文件、發布紀錄及官方套件 metadata，保留來源、適用條件與查核日期；重用歷史研究時區分沿用基線與本輪新增證據。
2. THINK 依已載入規則比較可行方案，結合專案約束提出決策與替代方案取捨，交叉檢查各項決策的相容性；將證據不足、待使用者確認及需實際驗證的限制分別交代清楚。

## Phase 3 -- 寫入並驗證研究與技術棧

1. READ 讀取 `templates/research.md`；需要判斷內容粒度、版本表或來源如何呈現時，再參考 `templates/research.example.md` 的相關段落。
2. WRITE 依已讀模板及已載入規則，按實際問題展開研究項目並寫入研究文件，清理填位符號與填寫提示。優先使用指定路徑，否則寫入來源規格同目錄的 `research.md`；無法由輸入或專案慣例判定位置時先確認。更新既有研究時保留仍有效的內容與研究 ID，改動處記錄對應查核日期。
3. READ 彙整技術棧前，讀取 `rules/techstack-summary-and-consistency.md` 與 `templates/techstack.md`，確認彙整判準及輸出骨架；需要對照分類粒度或完成品時，再參考 `templates/techstack.example.md`。
4. WRITE 依已載入規則與已讀骨架，從本次計畫的採用基線及已完成研究生成技術棧總覽，完成槽位與提示清理。優先使用指定位置，否則寫入研究文件同目錄的 `techstack.md`；更新時整合仍有效的既有項目。
5. READ 對照原始問題、已確認約束與已載入規則，核對研究決策的證據、替代方案及未解限制，交叉比對總覽的技術、版本、待定事項與章節連結，確認兩份文件的引用及模板結構完整；可由現有證據修正的問題直接修正，仍缺證據或決策的部分保留具體待確認內容。
6. WRITE 交付研究與技術棧總覽的文件路徑、主要決策、檢查結果與剩餘事項，明示哪些問題仍阻擋後續規劃、哪些可留待實作驗證，交回原呼叫流程。
