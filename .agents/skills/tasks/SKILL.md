# 實作任務規劃

以當前專案的需求與契約建立或更新任務清單。只交付規劃與規劃品質檢查，清單中的實作及產品驗收由後續執行流程承接。

# SOP

## Phase 1 -- 確認來源與可拆解範圍

1. READ 讀取本輪需求、相關對話、指定來源及既有任務文件，確認來源版本、功能邊界、輸出位置與路徑基準。
2. READ 讀取 `rules/source-scope-and-gaps.md`，取得來源充分性、缺口與前置任務產物的判定方式。
3. READ 讀取目標 repo 的 `constitution/README.md`，再依[憲法套用約定](../constitution/SKILL.md#憲法套用約定)載入適用的 `constitution/shared/rules.md` 與 `constitution/tasks/rules.md`。實際採用 OpenAPI 或 DBML 時，分別讀取 `constitution/api-plan/rules.md` 或 `constitution/data-plan/rules.md`。其他上游產物按索引與交接定位。核對上游就緒結果與現行版本。需裁決任務分組呈現時，先讀 `rules/precise-references-and-quality.md` 的可覆寫項目。
4. THINK 依已載入規則核對可用來源，區分阻擋實作的來源缺口、既有能力與可由前置任務建立的成果，列出可安全拆解的範圍。
5. WRITE 若存在阻擋缺口，提出最小必要問題或產出交給原分析主責的缺口交接；保留待確認狀態，只接續不受缺口影響的範圍。

## Phase 2 -- 拆解責任與可驗證任務

1. READ 讀取 `rules/task-decomposition-and-dependencies.md`，取得責任分組、實作與測試落點及相依判定方式。
2. THINK 依來源適用的故事或需求增量，整理共用前置、各責任的實作與接線、驗證工作及必要交付工作，為每項任務指定檔案落點、具體動作與可驗證完成條件。
3. THINK 核對任務與來源需求的覆蓋，收斂各增量的獨立驗證入口、所需前置及檢查點，合併重複工作並移除本輪範圍外的任務。

## Phase 3 -- 建立精確閱讀與執行順序

1. READ 讀取 `rules/precise-references-and-quality.md`，取得逐任務閱讀分級、語意定位與品質檢查方式。
2. THINK 為每項任務選定最小相關來源區段、Must Read／Optional 等級及讀取用途，核對定位實際存在，補齊按需觸發條件與前置產物的建立任務。依任務責任引用需讀取的規則和契約定位，將待實作驗證的條件納入完成條件。
3. THINK 依已載入規則核對真實前置、接線等待與共用檔案修改順序，形成可執行的相依關係、平行批次及 `[P]` 標記。

## Phase 4 -- 完成任務文件與品質交付

1. READ 讀取 `templates/tasks.md` 確認本輪適用結構；只有需要對照任務粒度、閱讀定位或填寫方式時，才讀取 `templates/tasks.example.md` 的相關任務，將其中虛構路徑視為寫法示例。
2. WRITE 在確認的輸出位置建立或更新任務文件，依實際範圍填入任務、閱讀指引、檢查點、相依、平行範例、策略與統計，保留尚待確認事項。
3. READ 依已載入規則逐項檢查來源覆蓋、定位與連結、任務落點、完成條件、相依與平行安全、編號統計及完成狀態；修正可由既有來源解決的問題，新增阻擋缺口時回到最早受影響階段。依適用憲法驗證 tasks 文件本身及下游交接覆蓋。
4. WRITE 交付任務文件位置、拆解範圍、實際執行的規劃品質檢查及剩餘缺口，明確區分任務文件就緒與產品實作驗收。在既有任務或來源索引交接規則版本、契約定位與應取得的證據。
