# Rule 1 - 視覺依據按缺口補足，HTML 是必要畫面交付

- Level: `MUST`
- 有 UI 責任時交付可直接開啟的單檔 HTML 與短紀錄。先核對既有品牌、元件、設計系統及畫面，足夠時沿用；缺口只補本輪受影響部分，不固定重做視覺研究。
- 需要新視覺方向時，依實際 UI UX Pro Max skill 的 design-system 流程取得候選；局部配色、字體、配置或互動問題採對應檢索。候選須經業務、角色、資訊密度、語言、裝置與無障礙篩選，取捨簡記於 Markdown。
- 工具推薦的行銷結構、資料圖表或動態效果不構成新需求。已有 Pencil 或其他設計可作來源，但操作、狀態及恢復仍由 HTML 表達；不固定委派畫布、不維護雙份原型、不以 `.pen` 或截圖代替可操作成果。

## Good Example

```md
沿用既有後台元件，只補缺少的結果未知狀態；需要對比建議才做局部視覺檢索。
既有 Pencil 提供欄位與配置來源，HTML 承接實際輸入、拒絕及恢復。
```

## Bad Example

```md
每個需求先重做配色與字體、委派 Pencil，再要求雙份原型及固定 PNG 交付。
搜尋結果推薦監控儀表板，所以單一調整表單新增即時訂閱與圖表。
```

# Rule 2 - 單檔原型必須可操作且清楚標明模擬邊界

- Level: `MUST`
- HTML 內含必要 CSS／JavaScript；以本地字體、內嵌圖形或可用替代呈現，直接開啟即可使用，不要求安裝、建置、登入或啟動真實後端。只讀外部素材若有必要須不妨礙主要流程及離線檢視，並列明依賴。
- 用記憶體假資料分開模擬服務狀態與呼叫者投影；角色切換、注入失敗、通知及重置置於明確標為原型評審工具的區域，正常產品流程維持使用者語言，不暴露 operation ID、版本除錯資訊或工程選項。
- 主要入口、輸入、提交、回饋與結果有實際行為；依本輪來源加入必要角色、拒絕、未知結果及恢復。示範控制需可重置、可重現代表性狀態；有分支難以自行發現時提供精簡導覽，不固定導覽組數或步數。
- 暫存及刷新行為說清楚：預設重開 HTML 重置記憶體；模擬同 session 重讀不得稱真正重載持久化或跨瀏覽器同步。沒有來源需要時，不加入資料庫、持久儲存或正式登入。
- 模板只固定結構與互動承載方式；依案例增減操作、欄位、狀態、角色及視覺。真正副作用與機密不放入原型；同檔假資料不能證明服務授權或保密已實現。

## Good Example

```md
雙擊 index.html 可使用；產品區提供正常表單，評審區切換角色並模擬回覆遺失。
同一次命令先變更假服務，再丟失回覆；確認操作回放原結果，可看到未重複寫入。
真實刷新重置；「重新同步」只模擬記憶體服務讀取，正式持久化仍待開發。
```

## Bad Example

```md
HTML 只是按鈕與靜態卡片；每次失敗只切一個標籤，無法重試或走下一步。
頁面先要求 npm install、登入正式服務；把 debug role 和清空資料放在產品主流程。
```

# Rule 3 - 畫面檢查與互動檢查必須實際執行

- Level: `MUST`
- 開啟實際 HTML，走過本輪主要流程及角色差異，操作代表性輸入錯誤、業務拒絕、等待與適用恢復；確認顯示資料、操作可用性、輸入保留／清除與服務契約一致，不只看靜態 DOM 或工具成功訊息。
- 視覺檢查包含實際文字字形、長內容換行、前景背景對比、資訊優先序、指定裝置可讀性及主要操作；互動檢查包含鍵盤、焦點、重複提交、未知結果與版本倒退等本案適用風險。修正後重跑受影響情境即可。
- 檢查截圖與工具紀錄可保留暫存作證據，不新增固定交付。瀏覽器不可用或必要情境無法操作時，記未執行及影響，保留待補／待修正，不把語法通過等同原型可用。
- 真實授權、並行交易、跨裝置、讀屏及公開部署，只有實際執行相應環境檢查才可宣稱通過；原型完成與正式開發完成分開。

## Good Example

```md
實測一般提交、無權限拒絕及結果未知回放；窄畫面仍能讀完錯誤並用鍵盤恢復。
修正重連後重複提交問題，再走該恢復情境。未驗證真實服務及讀屏。
```

## Bad Example

```md
檔案存在且 JS 可解析，因此所有流程、裝置及安全測試通過。
瀏覽器未能開啟，但因文件已寫完，整體標為完成。
```
