# 領域分析共同交接契約

供 `system-analysis`、`ui-ux-plan`、`api-plan`、`data-plan` 共用。獨立呼叫子 Planner 時沿用來源、產物與驗收規則，無須先有 Plan 或完整研究。

## 任務與產物邊界

界面用來檢查覆蓋，任務按責任與必要依賴組織；同一責任下共用模型、身分或恢復流程的界面可以合併分析。不因界面數量建立同數量檔案，也不為簡化而刪除實際互動。

一次交接須能辨認：本輪範圍與相鄰責任、實際可讀來源、已確認約束、必要前置結果、主責、唯一寫入位置、所需下游結果及未決影響。從已有資料補齊即可，不要求使用者重填表。設計判斷由領域主責完成；缺少業務規則、權限或範圍決策時，交回呼叫者或 `/clarify`，其餘部分繼續。

## 五類交付與單一來源

| 交付 | 主責與內容 | 預設位置（相對於功能規格目錄） |
| --- | --- | --- |
| Plan | system-analysis：邊界、流程、共同約束、分工索引、必要依賴、未決影響與實際狀態。 | `plan.md` |
| OpenAPI YAML | api-plan：實際 HTTP 操作與共用 components；session、事件、第三方協定及必要執行約定放在具名 `x-*` 擴充區。 | `analysis/api.openapi.yaml` |
| DBML | data-plan：本輪模型、鍵與關聯、值域；最相關 Notes 承載交易、授權、投影與生命週期約束。 | `analysis/data-model.dbml` |
| HTML prototype | ui-ux-plan：可直接開啟的單檔互動原型，用假資料檢視主要操作、角色、狀態與恢復。 | `analysis/ui/index.html` |
| UI／UX Markdown | ui-ux-plan：原型入口、使用方式、畫面意圖、契約對照、限制與實際檢查。 | `analysis/ui-plan.md` |

- 使用者指定位置與命名優先。預設每類一份整合產物；有 UI 時 HTML 與簡短紀錄一起交付。確實無 UI、服務或資料責任時，在 Plan 說明不適用，不生成空殼或虛構功能。多個獨立應用需要分開時仍限這五類，理由與各自責任寫在索引。
- 非 HTTP 契約放入 OpenAPI `x-realtime`／`x-interfaces` 等區域，保留傳輸、訊息及授權語意；無 HTTP 時使用 `paths: {}`。擴充區不是標準 HTTP operations，不用假 route 掩飾，也不宣稱一般 OpenAPI 工具會驗證其內部語意。
- 不另交獨立 session／Realtime／維運 YAML、資料說明 Markdown、`.dbdiagram`、Pencil 檔或固定預覽圖。可用既有設計作參考，必要畫面由 HTML 表達；檢查截圖、日誌或工具暫存不是新的分析交付。
- 一份產物只有一個寫入主責；HTTP 與事件契約交給同一 API 任務整合，UI 操作及同步體驗也由同一 UI 任務維護。避免多個平行工作共寫同檔。
- `system-analysis` 維護 Plan，其餘 Planner 只寫分配的領域產物。UI 可以製作分析用 HTML 原型，不實作正式應用、連線真實服務或部署；原型模擬的角色與資料不構成正式授權保證。

## 內容深度與追溯

- 先完成本輪業務操作所需的模型、服務及體驗。來源可在前言或影響決策的位置直接引用；共用未決事項集中於 Plan，子產物只補充局部影響，獨立呼叫且無 Plan 時在自身最相關位置保留。
- 格式承擔真實契約：OpenAPI 的 operations/components、DBML 的結構/Notes、HTML 的畫面與行為。Markdown 記錄原型意圖與交接差異，不複製完整 API、資料欄位或每個畫面的所有文字。
- 保留 caller 信任、資料權威、授權及可見性、狀態前置、原子性、競態、冪等與未知結果、通知與權威讀取分工。依實案處理，PVP 規則、Supabase、特定 DTO 名稱及範例數量不是通則。
- 最低執行設定與影響契約的限制留在 Plan／API／DBML。發布、備份演練、輪替、監測與 CI 的詳細程序，只在本輪需求確實依賴時展開於相關位置；尚未完成的公開配置須保留啟用限制與接手時點。
- 省略重複任務摘要、逐工作交接矩陣、不適用分支填表與完成宣告。必要來源、未知、部分可用性及檢查證據仍須可辨認，不以少寫掩蓋缺口。

## 骨架與範例的載入

- 先依本案需求、有效來源與適用規則分析。新建產物時讀取骨架的適用結構；更新或修正時先讀現行產物、變更需求與受影響依賴，沿用有效內容，需新增或重整結構才補讀骨架。來源及跨產物一致性所需的實際內容仍須讀取，不因省略範例而縮減分析或驗收。
- 範例對照有明確觸發條件：本輪首次採用組合 schema、複合關聯、非 HTTP 擴充或角色／恢復互動，且無有效表示可沿用；需對照同一規則在多個區塊或產物間如何維持一致；或檢查已發現結構／語意衝突，需要示範協助定位。其他情況由來源、規則與骨架直接產出，不固定全文讀取 example。
- 讀取前先判斷需要局部示範或整體配合，再依下表定位最小但完整的範圍，連同必要定義、引用及前後關係一起讀取。可預見需對照大量區塊時直接選擇整體範圍；以章節、物件或函式定位，不以固定行數截斷語意。

| 產物 | 範例對照範圍 |
| --- | --- |
| Plan | 對應的邊界、共同約束、分工／依賴或未決章節；需要理解整體分析深度時讀完整 Plan。 |
| OpenAPI | 相關 operation、共用 schema／response 及其必要 `$ref`；狀態組合或非 HTTP 語意連同相關分支、擴充區及權威讀取一起對照。 |
| DBML | 相關表、鍵、Ref 與 Notes；共同交易、授權或投影連同 Project Note 及受影響模型一起對照。 |
| HTML prototype | 相關互動的狀態、角色投影、送出／套用結果、同步、render 及必要呼叫處；不因骨架有評審工具就加入本案不適用的情境。 |
| UI／UX Markdown | 相關操作、恢復、UI 實作注意事項或檢查章節，依實際問題獨立選取。 |

- 若片段仍不足以解釋整體配合、需繼續跨多處補讀，或使用者要求沿用完整案例，擴大至相關完整 example 的對照範圍，沿用已取得的有效片段，只補尚缺上下文。內容已足夠時停止補讀，不因累積讀取比例而重讀全文；工具回傳截斷時依尚缺區段分批取得。跨產物示範依所需鏈路選取，範例間的連結不代表必須遍讀整組，也不取代本案的權威來源。
- 範例只提供結構與設計配合的示範。缺少本案業務、權限或產品決策時，回報局部未決，不以案例政策補成定案。正式產物所需的 request／response／訊息 examples 及其驗證照原規則執行；模板雙檔保留不代表每次必須全部載入。
- 仍在可用上下文且版本有效的內容可沿用；來源變動或上下文不足時補讀受影響範圍。新增通用判準前先核對既有規則，只有範例獨有且影響品質的判準才補至最相關的規則，避免以多份摘要重述同一要求。

## 回收、狀態與接續

回傳實際產物位置、可供下游使用的內容、檢查方式與結果、未決影響及新依賴；短訊息或產物相關位置足夠，不另造交接檔。可用狀態：待執行、分析中、待補輸入、待修正、已完成、不適用；以必要成果的實際內容與可用性判定，Plan 不必固定展開狀態大表。

主流程讀回後才驗收：核對格式與內部引用、需求／資料／服務的共同含義、來源衝突、角色可見性與失敗恢復。UI 須實際開啟並操作要求的主要流程與代表性錯誤／恢復、檢視指定裝置；工具不可用時列未執行及影響，必要原型無法產出或檢視時保持待補或待修正。

非阻塞未知要有明確影響與處理時點；缺少必要決策只阻塞依賴它的結論。來源變動後回查實際受影響產物，仍有效部分沿用；不得把範例的過往檢查結果抄成本次證據。只有本輪必要成果及跨產物交接通過才能稱分析完成，且仍要區分語法檢查、假資料原型、服務整合與公開部署。
