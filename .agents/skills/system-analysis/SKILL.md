# SOP

## Phase 1 -- 確定範圍與可用輸入

1. READ 讀取使用者需求、專案規範、既有規劃及界面分析產物，確認本次要建立、更新或接續的範圍與實際可用來源；使用者明確只要規劃時，記錄本次停止於規劃交付。
2. THINK 界定規劃粒度、來源、輸出路徑、共同約束取捨或缺口影響時，先讀取 `rules/planning-scope-and-sources.md`，再確定本次可採用的規劃依據與待確認事項。
3. WRITE 若存在無法形成合理規劃的重大缺口或來源衝突，提出最少必要問題並等待答覆；其餘缺口記錄影響範圍，繼續不受影響的規劃與分析工作。

## Phase 2 -- 形成系統輪廓與分析流程

1. THINK 依需求、已確認輸入及已載入規則整理系統邊界、模組責任、核心流程、共同約束、大致專案結構、MVP 交付依賴及未決事項；保留規劃所需粒度，讓後續子技能承接詳細設計。
2. THINK 規劃端點界面及分析順序時，先讀取 `rules/endpoint-interface-wave-planning.md`，再完成端點分類、各界面的獨立分析工作與符合依賴的波段安排。
3. THINK 為各工作選擇主責 Planner 時，先讀取 `rules/planner-dispatch-and-execution.md` 與 `references/interface-analysis-contract.md`，再逐項確定委派對象、交接輸入、產物位置及可沿用的既有結果。

## Phase 3 -- 保存可執行的分析計畫

1. READ 讀取 `templates/plan.md` 與 `templates/plan.example.md`，依骨架組織規劃、參考範例改寫圖表、目錄、波段及工作執行紀錄。
2. WRITE 將規劃寫入已確定的輸出檔，沿用可用的既有內容，以實際來源改寫前言，使用清楚一致的名稱連結界面、分析工作及前置輸入。
3. READ 依已載入規則檢查已寫入內容的來源、粒度、共同約束、界面覆蓋與波段依賴，確認規劃及待執行事項清楚區分，移除未替換槽位與填寫提示；發現缺漏或矛盾立即修正。
4. WRITE 保存每項工作的主責、輸入、產物路徑與真實狀態；本次明確只要規劃時回報後停止，其餘進入界面分析。

## Phase 4 -- 依波段委派並承接分析

1. THINK 依已載入規則核對本波段各工作的必要輸入與既有結果，選出可啟動的工作；發現新依賴或輸入變更時，先修正計畫及受影響狀態。
2. DELEGATE 依計畫逐項呼叫 `/ui-ux-plan`、`/data-plan` 或 `/api-plan`，交付單一界面任務與已確定的輸入及輸出位置；符合平行條件時分別委派，環境只支援逐項呼叫時保持相同依賴順序執行。
3. READ 讀取回傳產物及其內嵌分析，核對任務範圍、來源、必要交接、適用的結構定義與共同約束；不足時交回同一主責 Planner 修正，阻塞時記錄缺少輸入與受影響工作，不代寫其專業結論。
4. WRITE 將已驗收結果、未決事項及狀態寫回規劃，將可用產物交給後續工作；重複本階段直到所有適用工作完成，或剩餘工作均需尚未取得的輸入。

## Phase 5 -- 核對整體結果並交付

1. READ 對照界面清單、工作紀錄及實際產物，檢查覆蓋、名稱、跨界面契約、權限、狀態與資料責任的一致性；有落差時定位主責並回到受影響工作的分析與依賴檢查。
2. WRITE 更新規劃的整體分析狀態與產物連結，回報完成界面、待補輸入、影響範圍及下一步；只有所有適用工作及必要交接均通過檢查時，才宣告整體分析完成。
