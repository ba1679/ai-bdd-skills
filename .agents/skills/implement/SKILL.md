# 任務實作

依 Tasks 的責任、完成條件與驗收來源交付可運作的增量。
預設 one shot：在已授權範圍內持續實作、修錯與驗證，直到本輪任務完成；不逐項向使用者回報，也不在每個任務或故事完成後等待確認。長時間工作只回報有意義的發現、方向改變或阻擋。one shot 不取代必要澄清，也不允許以未驗證成果宣稱完成。

# SOP

## Phase 1 -- 確認執行範圍與基線

1. READ 讀取使用者指示、已確認決策、適用專案規範及指定 Tasks 全文，確認本輪範圍、路徑基準、任務、相依、檢查點與證據位置；未指定目標時先從 context 與專案定位，仍無法判定才確認目標。
2. READ 檢查工作目錄、相關實作、測試、版本及可用指令，辨識已有能力、未提交修改與環境限制，保留既有工作。
3. READ 首次核對任務狀態時，讀取 `rules/evidence-and-status.md`，據此核對既有完成證據並標記需重驗範圍，形成可信的起始狀態。
4. DELEGATE 首次選擇基線檢查時，讀取 `rules/verification-and-repair.md`，執行必要且可用的相關檢查並保存結果；尚待任務建立的工具或 fixture 記錄建立者及可驗證時點。

## Phase 2 -- 選取就緒任務並收斂約束

1. THINK 首次選取任務時，讀取 `rules/task-readiness.md`，依已載入規則核對相依並選取前置已滿足的未完成任務；有循環、引用衝突或缺漏時，先依已確認來源修正可確定的部分。
2. READ 依所選任務的閱讀指引載入必要來源，核對實際落點、消費者與前置產物，掌握當前完成條件及契約；收斂仍無法確認的缺口。
3. THINK 依使用者目標、context、既有架構及慣例決定一般實作選擇，記錄有影響的假設；完成寫入集合與批次安全判定後，才准許進入實作。
4. DELEGATE 僅對查核後仍無法確認且影響需求或驗收正確性的決策呼叫 `/clarify`，交付原需求來源、缺口與已查 context、受影響 Task ID 及既有澄清狀態。沿用其提問、預算及保存流程；等待期間暫停依賴答案的工作，可選其他就緒任務。收到結果後回到本 Phase 核對受影響來源、任務及證據，未解決者保持阻擋。

## Phase 3 -- 完成小步實作與正式接線

1. THINK 決定當前任務的最小可驗證改動與測試順序，依已載入規則選擇必要的測試先行、bug 重現及回歸方式。
2. WRITE 沿用既有抽象完成程式、必要設定、測試與正式接線；保持已確認契約，將重構及依賴變更限制在本輪必要範圍。實際寫入集合或前置改變時，先回 Phase 2 重判執行安全。
3. READ 檢查本次差異、呼叫端及正式入口，核對需求符合性、接線、錯誤處理與範圍外變更；修正遺漏後進入驗證。

## Phase 4 -- 驗證修復並完成增量驗收

1. DELEGATE 依已載入規則執行當前任務必要檢查，對照自身完成條件判定結果；失敗時以輸出、差異及最小重現定位根因，回 Phase 2 或 3 修正並重驗。記錄無法自行解除的外部阻擋，保留受影響任務未完成。
2. DELEGATE 每個故事或需求增量的實作及正式接線就緒時，即執行 Tasks 指定的獨立驗證與檢查點；失敗返回對應任務修復，不延至所有故事完成才驗收。
3. WRITE 依已載入規則保存任務與增量的實際驗證證據、更新完成狀態並標記失效證據；安排受後續修改影響的重驗。
4. THINK 仍有可執行任務或必要重驗時回 Phase 2；任務失敗只阻擋其依賴工作。全部本輪必要工作完成，或剩餘工作皆有具體外部阻擋時，進入交付核對。

## Phase 5 -- 核對最終版本與交付

1. DELEGATE 在最終整合版本執行來源要求的跨故事品質門檻、受影響回歸及必要建置，確認覆蓋本輪適用需求與成功條件；尚未解除的阻擋如實保留。
2. READ 核對最終差異、需求契約、全部本輪任務與有效證據；發現已確認來源可決定的漏項即局部補入 Tasks，返回 Phase 2 執行。新需求決策回到必要澄清；不以補勾或重編清單代替工作。
3. WRITE 以繁體中文交付實際成果、Tasks 與證據位置、已執行驗證結果及未完成項目與原因；依已載入規則判定交付狀態，清楚揭露未驗證能力及外部限制。

已載入且未變更的規則可在後續循環沿用；檔案變更或上下文遺失時，回到相應載入點重讀後再執行。
